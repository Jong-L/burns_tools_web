# 前端目录结构重构方案

## Context（为什么做这件事）

现状：`frontend/` 用 Next.js 16 App Router，`app/[lang]/` 是官方 i18n 路由方案（文档 `node_modules/next/dist/docs/01-app/02-guides/internationalization.md` 明确要求把特殊文件放在 `app/[lang]/` 下，根布局也允许嵌在那里）。**所以 `[lang]` 不是冗余，要保留。**

但用户感觉"嵌套过分"，排查后确认真正的别扭之处不是路由层级（那是框架硬性约定），而是三类可清理的问题：

1. **相对路径过深**：`app/[lang]/tools/[toolId]/page.tsx` 里要写 `../../../../data`，层级一深就极易写错。
2. **非路由文件混在路由目录里**：`useLang.jsx`、`LanguageSwitch.jsx`、`icons.jsx` 直接躺在 `app/` 根下；`app/[lang]/App.jsx` 名字像"应用根"，实际只是首页 Hero 组件，与路由的 `page.jsx` 职责混淆。
3. **后缀混用**：`tools/page.tsx`、`tools/[toolId]/page.tsx` 是 `.tsx`，其余全是 `.jsx`，而代码里零类型标注，后缀名实不符。

预期结果：目录一眼能分出"哪些是路由、哪些是组件"，所有跨目录导入用 `@/` 别名，后缀统一。**不改动任何页面渲染逻辑、URL 结构与 i18n 机制。**

## 已确认的决策

- 保留 `app/[lang]/`，URL 维持 `/zh`、`/zh/tools` 前缀。
- 非路由文件移到 `app/_components/`（官方"私有文件夹"约定，下划线前缀不参与路由）。
- 后缀统一为 `.jsx`。

## 实施步骤

### 1. 配置路径别名

`frontend/tsconfig.json` 的 `compilerOptions` 增加：

```json
"baseUrl": ".",
"paths": {
  "@/*": ["./*"]
}
```

映射到项目根，因此 `@/data`、`@/config/i18n`、`@/assets/...`、`@/app/_components/...` 均可用。Turbopack 与 Next 原生支持。

### 2. 移动并重命名非路由文件

| 原路径 | 新路径 |
| --- | --- |
| `app/useLang.jsx` | `app/_components/useLang.jsx` |
| `app/LanguageSwitch.jsx` | `app/_components/LanguageSwitch.jsx` |
| `app/icons.jsx` | `app/_components/icons.jsx` |
| `app/[lang]/App.jsx` | `app/_components/HomeHero.jsx`（改名：它只是首页 Hero） |

`app/globals.css` **保持原位**（全局样式入口，由根布局导入，属约定位置）。

### 3. 统一后缀为 `.jsx`

- `app/[lang]/tools/page.tsx` → `tools/page.jsx`
- `app/[lang]/tools/[toolId]/page.tsx` → `tools/[toolId]/page.jsx`

两个文件内容里没有任何 TS 语法，仅需改名，无需改代码。`tsconfig.json` 保留（不影响构建）。

### 4. 改写全部导入为 `@/` 别名

需修改的文件与要点（模式一致：跨目录一律 `@/`，同目录保持相对路径）：

- `app/[lang]/layout.jsx`：`../../data` → `@/data`；`../../config/i18n` → `@/config/i18n`；`../useLang` / `../LanguageSwitch` / `../icons` → `@/app/_components/...`；`../globals.css` 不变。
- `app/[lang]/page.jsx`：`../../data` → `@/data`；`./App` → `@/app/_components/HomeHero`。
- `app/[lang]/tools/page.jsx`：`../../../data` → `@/data`；`../../../data/tools` → `@/data/tools`；`../../icons` → `@/app/_components/icons`。
- `app/[lang]/tools/[toolId]/page.jsx`：`../../../../data` → `@/data`；`../../../../data/tools` → `@/data/tools`；`../../../icons` → `@/app/_components/icons`。
- `app/_components/HomeHero.jsx`：`../icons` → `@/app/_components/icons`。
- `app/_components/LanguageSwitch.jsx`：`./useLang` 不变；`../data` → `@/data`。
- `app/_components/useLang.jsx`：`../data` → `@/data`。
- `data/tools.js`：`../assets/*.svg`（5 处）→ `@/assets/*.svg`；`./index` 不变。
- `data/index.js`：`../config/i18n` → `@/config/i18n`。

> 注意：`data/tools.js` 与 `data/index.js` 都在 `data/` 内，改成 `@/` 后不再有层级歧义。

### 5. 修正过时注释

`config/i18n.js` 第 8 行注释引用了旧路径 `app/LanguageSwitch.jsx`，改为 `app/_components/LanguageSwitch.jsx`。

### 6. 不改动的部分（明确排除）

- 不引入 `next/root-params` 去消除 `lang` 参数传递 —— 属额外重构，本次范围外。
- 不改 `proxy.js`、不改 URL 结构、不改 `data/*.json` 文案、不动 `globals.css` 样式。
- 不改任何组件的渲染结果。

## 重构后的目标结构

```
frontend/
├── app/
│   ├── _components/          # 非路由的共享 UI（下划线前缀，不参与路由）
│   │   ├── HomeHero.jsx      # 原 [lang]/App.jsx
│   │   ├── LanguageSwitch.jsx
│   │   ├── useLang.jsx
│   │   └── icons.jsx
│   ├── [lang]/               # 官方 i18n 动态段（保留）
│   │   ├── layout.jsx        # 根布局：<html>/<body> + 顶栏 + 氛围层
│   │   ├── page.jsx          # /zh
│   │   └── tools/
│   │       ├── page.jsx      # /zh/tools
│   │       └── [toolId]/page.jsx   # /zh/tools/:id
│   ├── globals.css
├── assets/  config/  data/
├── proxy.js  tsconfig.json  eslint.config.mjs
```

## 验证方式

1. `npm run build`（在 `frontend/` 下）—— 构建通过即证明所有 `@/` 别名与移动后的路径都解析正确，这是最主要的验证手段。
2. `npm run lint` —— 确认无未使用导入 / 失效路径。
3. `npm run dev`，浏览器依次访问：
   - `/` → 应重定向到 `/zh`（`proxy.js` 行为未变）
   - `/zh` → 首页 Hero 正常，顶栏品牌名正常（语言切换按钮因只发布 zh 而隐藏）
   - `/zh/tools` → 5 个工具卡片正常
   - `/zh/tools/thought_journal` → 工具详情占位页正常
   - `/zh/tools/不存在` → 走"未知工具"兜底文案
   - 直接确认页面 HTML 的 `<html lang="zh">` 与 `<title>` 仍按语言生成（SEO 未受影响）
